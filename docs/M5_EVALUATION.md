# M5 选镜评估

**目标**：用人工标注量出「自动选镜」有多准，给打分权重、向量检索、将来的 LLM 重排提供改进依据。对应退出标准「两部测试片，人工审阅：需要替换的镜头占比 ≤ 30%」——首选可接受率 ≥ 70% 是它的代理指标。

## 它量什么

对每条标注（一段解说文案 + 它引用的场景 + 人认为可接受的镜头），用**与计划构建相同的排序**（`stages/creation/selection.py`：候选 → 打分，有向量索引时带向量检索；默认权重）给全片镜头排序，然后：

| 指标 | 含义 | 目标 |
|------|------|------|
| 首选可接受率 | 排第一的镜头是否在可接受集合里，所有标注的比例 | ≥ 0.70 |
| top-k 命中率 | 前 k 个（默认 5）里至少有一个可接受镜头的比例 | ≥ 0.90 |
| top-k 召回 | 前 k 个里命中的可接受镜头数 ÷ min(可接受数, k)，对标注取平均 | 参考 |
| MRR | 第一个可接受镜头名次的倒数，取平均 | 参考 |

目标值是起点，不是验收线；第一次在真实影片上跑出来后再定。排序不含「复用惩罚」（每条标注独立评估）。

## 怎么标

1. 先跑完分析，直到场景和镜头描述都有：`offscreen stage analysis.scenes --asset <影片>`（要测向量检索，还需配置嵌入器并跑 `analysis.embeddings`）。
2. 在分析页或 `GET /api/assets/{id}/index/shots`、`index/scenes` 里看镜头和场景编号。
3. 为**每部测试片至少 20 段**写标注文件：文案取自真实生成的文案（不同风格各取几段），`acceptable` 列出**所有**画面合适的镜头，不要只写最好的一个——写少了会把正确的选择算成错。

```json
{
  "labels": [
    {
      "id": "q01",
      "text": "女孩在雪山里发现了一条受伤的龙。",
      "scene_refs": ["sc_003"],
      "acceptable": ["sh_0031", "sh_0032"],
      "note": "第 2 个镜头里龙在画外，不选"
    }
  ]
}
```

4. 导入、评估：

```bash
offscreen select import <asset> labels.json     # 场景和镜头编号会被校验，写错立即报错
offscreen select evaluate <asset> -k 5
offscreen select export <asset>                 # 取回已保存的标注
```

标注存在 `data/annotations/<asset>/selection.json`，与任何分析产物分开，重新分析不会动它。

## 怎么用结果

- 「不在前 k 个」的标注是排序真正漏掉的：看 `note` 和镜头描述，判断是描述不准（回到镜头描述）、候选没覆盖（`scene_refs` 之外的镜头）还是权重不当。
- 「找到了但不是第一」的标注说明召回够、排序不够：调 `ScoringWeights`，或接入 LLM 重排（见 PARKING_LOT）。
- 调权重前后各跑一次 `select evaluate`，只在指标整体变好时才改默认值；同一批标注别反复调到过拟合——留一部分标注不参与调参。
