## 3. 换到真实环境后的验证顺序

1. 装可选依赖：`uv pip install insightface onnxruntime sentence-transformers transnetv2-pytorch faster-whisper`。
2. 把两部测试片放进 `media_roots`，导入，点「分析」（耗时与费用看报告）。
3. 切点：标注 → 评估 → 对比两种检测器 → 决定默认检测器（换检测器会让 shots 之后的阶段全部重算，包括花钱的镜头描述，换之前先定）。
4. 人物：点「识别人物」，在面板里看簇和名字，记下过碎 / 过并的情况，据此校准聚类阈值。
5. 搜索：对 embeddings 阶段建好的索引搜 20 句话，人工判断前 5 个。
6. 场景摘要：抽查 20 个。
7. 把结果写回本文件和 `docs/PROVIDERS.md`，勾掉退出标准。

## 4. 已知缺口（不阻塞 M4）

- 人脸 / 人物 / 命名 / 向量阶段不在默认「分析」链里（人脸检测在 CPU 上约 25 分钟 / 两小时电影），各有独立按钮或命令；所以场景里的人物字段、故事里的人物关系目前为空，文案（M4）和选镜（M5）暂时读不到人物。何时并入默认链，取决于真实片上的效果与耗时。
- 合并后的人物在 `cast.json` 里仍是旧编号；读取方需要用 `GET /assets/{id}/index/characters` 返回的 `merged` 映射。
- 分析前的 token 估算与确认闸门没做（`docs/PARKING_LOT.md`）。
