# M1 复盘（M1-15）

在 Sintel（720p，14 分 48 秒，英文外挂字幕）上执行 `offscreen run-all sintel.mkv --minutes 3`，记录结果、问题清单和对 M3–M7 优先级的建议。

## 2. 问题清单

按对成片质量的影响排序。

1. **场景粒度过粗，选镜几乎没有依据。** story 阶段对整部 14 分钟的片子只切出 2 个场景（0–590 s、590–888 s）。文案 18 段的 `scene_refs` 全落在这两个场景里，朴素选镜只能在一个 5–10 分钟的区间里按顺序取镜头，画面与句子的对应基本靠运气。→ M3-11 / M3-12。
2. **台词太少，纯靠对白做理解不够。** Sintel 只有 26 条字幕（大量内容是无对白的动作与画面），故事摘要几乎只来自这 26 句。→ M3-06（镜头视觉描述）是理解质量的决定项，不是锦上添花。
3. **文案引用不到具体台词。** `line_refs` 全为空，`kind` 全为 narration，没有"原声段"。→ M4 / M5-06。
4. **片头、标题卡会被选进成片。** 样张里出现了 SINTEL 片名标题卡。朴素选镜没有"片头片尾 / 屏幕文字"惩罚。→ M5-03 已含此项，M3-03 的画质指标可提供输入。
5. **成片比目标长 12%。** 目标 180 秒，实际 202 秒：配音时长由 TTS 决定，字数控制（4.5 字/秒）与实际语速有偏差，且没有回头校正。→ M5-05（时长适配）；M4 的字数估计应改用实测语速或 `char_timings`。
6. **叙事顺序偶有错位。** 开头钩子取自结尾场景（符合"钩子"设定），但画面与句子的对应没有做任何顺序约束。→ M5-03 的"时间顺序"项。
7. **渲染偏慢。** 76 个片段逐个起 ffmpeg 进程，CPU 上总计数分钟。目前可接受；M5-09 的单段预览会放大这个问题。→ M7-02 评估（片段合并编码 / 复用）。
8. **画幅保持源片 2.35:1（1280×544）。** 符合 M1 约定，竖屏 / 其他画幅属 M7。
9. **`scripts/fetch_fixtures.sh` 的 Sintel 地址失效**（`demo/movies/Sintel.2010.720p.mkv` 返回 404）。720p 版本现在在 `durian/movies/Sintel.2010.720p.mkv.zip`。已在本任务中修正。

做得对、不需要动的：引擎缓存与失效、阶段间只读上一层产物、JSON 降级模式（script 阶段"repairing draft"自动修复了 1 个校验问题）、TTS 缓存、整条链路无需 GPU 即可跑通（外挂字幕时不触发 ASR）。

## 3. 对 M3–M7 优先级的建议

| 方向 | 建议 |
|------|------|
| **M3** | 把 **M3-06（镜头视觉描述）→ M3-11（场景切分）→ M3-12（剧情理解 v2）** 置于最前，其余（人脸、人物 UI）后移。问题 1、2 是这三个任务直接解决的。M3-03 的画质 / 亮度指标顺带给问题 4 提供输入 |
| **M4** | 字数→时长估计用实测数据校准（问题 5）；文案生成时要求引用 `line_refs`，为 M5-06 的原声段铺路（问题 3） |
| **M5** | M5-02 / M5-03 的候选与打分依赖 M3-06 / M3-10 的输出，顺序不变；打分函数必须包含片头片尾惩罚与时间顺序（问题 4、6）；M5-05 的"总时长精确到帧"是对问题 5 的直接修复 |
| **M7** | M7-02 评估渲染并行度或片段合并（问题 7） |

M2（作业系统 + API + UI）不受影响，按计划推进。

## 4. 复现

```bash
scripts/fetch_fixtures.sh download                       # 需要网络
ffmpeg -i data/fixtures/sintel.mkv -map 0:3 data/fixtures/sintel.srt   # 内嵌英文字幕 → 外挂
cp config.example.yaml data/config.yaml                  # media_roots 改为 ./data/fixtures
cd backend && uv run offscreen run-all ../data/fixtures/sintel.mkv --minutes 3 -c ../data/config.yaml
```

需要环境变量 `MINIMAX_API_KEY`。

## 5. M3-12 之后的复测（同一部 Sintel、同一条 `run-all --minutes 3`）

分析链从「按台词切 2 个粗场景」换成 关键帧 → 镜头描述（视觉模型）→ 场景切分 → 分层剧情（M3-03 / 06 / 11 / 12）：

| M1 复盘的问题 | M1 时 | 现在 |
|---------------|-------|------|
| 1. 场景太粗，选镜没有依据 | 全片 2 个场景；文案 18 段的 `scene_refs` 全落在这 2 个场景里 | 15 个场景（与片头 / 打斗 / 帐篷 / 小镇 / 小龙 / 市集 / 巨龙 / 空镜 / 雪崩 / 巨树洞穴 / 字幕的真实结构吻合）；13 段文案引用了其中 14 个；**92 个片段全部落在被引用的场景内**，抽帧与字幕逐段对得上 |
| 2. 台词太少，只靠对白不够 | 剧情只来自 26 句字幕 | 镜头描述（含画面文字）进入场景摘要和剧情，剧情有 5 幕、5 个转折，结局带场景 id |
| 4. 片名标题卡被选进成片 | 出现 | 抽帧中未出现；仍有 3 个片段落在 `is_credits` 镜头上（M5-03 的片头片尾惩罚会处理） |
| 5. 成片比目标长 | +12%（202 s / 180 s） | **+44%（259 s / 180 s）**：13 段共 1019 字，按 4.5 字/秒应为 226 s，实际配音更慢。字数到时长的估算仍未校准，M5-05 / M4 才会处理 |

代价：分析一部 15 分钟的片子要多发约 37 个模型请求（镜头描述 28 个、场景 9 个、剧情 2 个），约 30 万 token、约 30 分钟（见 `docs/PROVIDERS.md`）。运行前的额度确认（`budget.confirm_above_tokens`）需要先知道镜头数，留给 M3-15 的分析报告一并做。
